# Wakapi 2.17.6 Redeployment Design

## Goal

Redeploy Wakapi on the root cluster from a signed Docker Hardened Image that
contains upstream Wakapi 2.17.6, including the critical shared-cache-key
authentication fix, while preserving the existing PostgreSQL data, OIDC,
SMTP, metrics, and GitOps release contracts.

## Ownership boundaries

- `/Users/yaelmeya/git/m0sh1.cc/wakapi-dhi` owns the application source,
  upstream integration, tests, DHI definition, image scan, signing, and GHCR
  promotion.
- `/Users/yaelmeya/git/m0sh1.cc/helm-charts/charts/wakapi-dhi` owns the public
  Kubernetes deployment contract and its OCI chart release.
- `/Users/yaelmeya/git/m0sh1.cc/infra/apps/user/wakapi` owns root-cluster
  configuration, chart vendoring, and the wrapper contract.
- `/Users/yaelmeya/git/m0sh1.cc/infra/root/argocd/apps/wakapi.yaml` owns
  deployment enablement. ArgoCD remains the only cluster writer.

## Source integration

Merge upstream tag `2.17.6` into the current Forgejo `master` lineage. Preserve
the fork's module identity, vendored dependency model, DHI build definition,
Forgejo release-tag workflow, and Woodpecker validation/build/scan/sign/promote
pipelines. Resolve the known conflicts deliberately rather than replacing the
fork with upstream wholesale.

The upstream regression tests for separated user-ID and API-key cache
namespaces are mandatory. The fork release version becomes
`2.17.6-yaelmoshi.1`; immutable Forgejo tags retain the
`v2.17.6-yaelmoshi.1-ym.N` suffix.

The `github.com/muety/wakapi` pseudo-module remains replaced by the local module
for historical imports. Renovate must stop treating that pseudo-module as an
upstream source sync because changing its pseudo-version does not change the
compiled application source.

## Chart contract

Add `existingSecrets.cookieKey` to the public chart. It injects
`WAKAPI_COOKIE_KEY` from a Secret key without putting key material into chart
values. Update the JSON schema, README example, CI values, Deployment template,
and rendering assertions. Release the next chart version with application
version `2.17.6-yaelmoshi.1` and the signed image digest.

## Infra and rollout

Create `root/secrets/wakapi-cookie-key.sealedsecret.yaml` by piping a randomly
generated 128-byte base64 key directly from a client-side Secret manifest into
`kubeseal`; never write plaintext key material. Add the SealedSecret to
`root/secrets/kustomization.yaml` and reference it from
`apps/user/wakapi/values-root.yaml`.

Update the wrapper dependency, lock file, and tracked OCI archive together;
preserve dependency alias `wakapi`; bump the wrapper chart version. Move the
Application from `root/argocd/disabled/wakapi.yaml` to
`root/argocd/apps/wakapi.yaml` and update `docs/app-catalog.md` to enabled.
Remove obsolete per-Application Image Updater annotations so Renovate and the
checked-in digest remain the single writer for this deployment.

Commit and push in producer-to-consumer order. Wait for the signed image and OCI
chart to exist before updating infra. Reconcile only with `argocd app sync` and
`argocd app wait`; do not mutate Kubernetes resources imperatively.

## Verification

- Fork: regression test red/green proof, full vendored Go suite, release-policy
  tests, Woodpecker PR/push validation, DHI build, Trivy HIGH/CRITICAL gate,
  Cosign verification, and GHCR digest inspection.
- Chart: schema validation, Helm lint, representative render, repository
  dependency/version checks, OCI pull, and digest verification.
- Infra: wrapper lint/render, vendored archive guard, policy suite,
  `mise run k8s:lint-changed`, SealedSecret placement checks, and Git diff check.
- Live: `root-apps-root` and `root-wakapi` Synced/Healthy, Deployment ready,
  exact image digest, clean migration/startup logs, `/api/health` HTTP 200,
  attached HTTPRoute, and a present VMServiceScrape.

## Expected user impact

Existing Wakapi data remains in the root CNPG database. The new persistent
cookie key intentionally invalidates any pre-existing ephemeral login cookies
once, so users must log in again after the upgrade; later pod restarts preserve
sessions.
