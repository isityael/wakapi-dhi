# Wakapi 2.17.6 Redeployment Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publish a tested and signed Wakapi 2.17.6 DHI release, publish its Helm chart with a cookie-key Secret contract, and redeploy it to the root cluster through GitOps.

**Architecture:** Work producer-to-consumer across the Wakapi fork, public Helm chart, and infra wrapper. Each released artifact is verified before its digest/version is propagated to the next repository; only ArgoCD reconciles cluster state.

**Tech Stack:** Go 1.26+, Docker Hardened Images, Woodpecker CI, Forgejo Actions, GHCR, Cosign, Trivy, Helm 3, Bitnami SealedSecrets, ArgoCD, Kubernetes, VictoriaMetrics Operator.

**Spec:** `docs/superpowers/specs/2026-08-21-wakapi-2.17.6-redeployment-design.md`

## Global Constraints

- Deploy upstream stable tag `2.17.6`, not unreleased upstream `master`.
- Preserve the fork's Forgejo/Woodpecker/DHI release chain and vendored Go build.
- Publish and verify producer artifacts before changing their consumers.
- Never write plaintext Kubernetes Secret material to disk or Git.
- Preserve unrelated worktree changes in all three repositories.
- Reconcile only through Git, ArgoCD sync, and ArgoCD wait.
